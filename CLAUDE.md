# Страви: особистий PWA для вибору й обліку страв

Мова інтерфейсу й коментарів: українська. Користувачка не розробник: пояснюй просто, роби малими кроками.

## Продукт
Мобільний PWA (Android), офлайн, дані локально (IndexedDB через Dexie). Каталог страв з ролями (гарнір / білок / повна страва), варіантами, структурованими інгредієнтами (обов'язкові, групи «або», дозволені заміни), смаковими тегами, часом і прапорцем духовки. Є список «Мої продукти», пошук за наявними продуктами, пари страв, фільтри, сортування, ручний порядок і тимчасове приховування страв.

## Стек
Vite + React + TypeScript, Dexie, react-router (HashRouter), dnd-kit, vite-plugin-pwa. Шрифти локально через @fontsource (у кеш PWA — лише кирилиця й латиниця). Хостинг: GitHub Pages, публікація GitHub Actions (`.github/workflows/deploy.yml`) після push у `main`, `base: './'`. Іконка — фаянсова тарілка з фестонним краєм і трьома фігурами ролей. `public/icon.svg` закруглена (вкладка браузера); `pwa-192/512.png` — з неї, прозорі кути; `pwa-maskable-512.png` і `apple-touch-icon-180.png` — повний квадрат (телефон сам обрізає форму). PNG рендерились headless Edge з SVG. README.md — опис для GitHub (українською).

## Стан
Етап 1 готовий: каталог (пілюлі ролей з множинним вибором, пошук, сортування, фільтри, приховування, ручний порядок), екран страви (фото, варіанти, інгредієнти, заміни).
Етап 2, порядок: 1) GitHub Pages і встановлення на телефон (зроблено), 2) додавання/редагування страви (зроблено: `DishForm.tsx`, чернетка й перетворення в `draft.ts`, стиснення фото в `photo.ts`), 3) «Мої продукти» (зроблено: `Pantry.tsx`, вкладки `Tabs.tsx`; порівняння продуктів без урахування регістру через `pantrySet`/`norm`), 4) експорт/імпорт даних (зроблено: кнопка вгорі каталогу, `Backup.tsx` + `backupData.ts`), 5) пошук за наявними продуктами (зроблено: `Search.tsx`, логіка `coverage`/`bestMatch` у `logic.ts`), 6) пари (зроблено: вкладка `Pairs.tsx`, секція «Пасує до» на сторінці страви, логіка `pairsData.ts`, вибір страви `DishPicker.tsx`). Етап 2 завершено.

## Дизайн «Тихий фаянс»
Білий фон, кобальт `#3149B8`, текст `#1F2A5C`, приглушений `#4A5690`, світлі фони `#EEF1FB`. Шрифти Unbounded (заголовки) + Onest. Ліній-фестон під заголовком. Асиметричні радіуси (`22px 22px 4px 22px` тощо). Пілюлі, а не вкладки.
- Роль кодується формою, кольором і значком, не лише кольором: гарнір — жовтий квадрат, білок — помаранчеве коло, повна — блакитна арка.
- Фото страв у різних формах і пастельних фонах, значок ролі внизу праворуч, духовка — іконка вгорі праворуч.
- У рядку каталогу: назва, «є: …» (зелений, що з обов'язкового вже вдома, разом із замінами «олія → масло») і «немає: …» (теракотовий) окремими рядками. Час і оцінки показуються лише при відповідному сортуванні; кількість інгредієнтів у рядку не показуємо. Категорію текстом не пишемо.
- Мінімум 44px для цілей натискання, кнопки з aria-label.
- У каталозі пошук, пілюлі ролей і рядок «N страв · сортування» ховаються кнопкою-стрілкою в заголовку (поруч із резервною копією; плавна анімація, стан запам'ятовується). Якщо в схованій панелі щось вибрано, на кнопці персикова крапка. Згортання під час прокрутки пробували — відмовились (стрибало). У заголовку «N стр.».
- Нижнє меню (`Tabs.tsx`): тонка лінія зверху (без фестона), лінійні іконки (миска, лупа, квадрат+коло для пар, кошик), активна вкладка — кобальт і світла пілюля з асиметричними кутами; у «Пари» активна іконка зафарбована кольорами ролей.

## Рішення
- Духовка — булевий прапорець, без температури. На сторінці страви — маленька пілюля «Духовка» біля ролі, лише коли потрібна.
- Кількості й грамування інгредієнтів не ведемо (поля `amount` немає). Базове «є завжди» (`STAPLES` у `logic.ts`: сіль, олія, цукор, чорний перець, паприка, лавровий лист) не пишемо як інгредієнти й не ведемо в «Моїх продуктах»; `pantrySet` вважає їх наявними (тож заміни «вершкове масло → олія», «мед → цукор» завжди спрацьовують). Dexie v3 одноразово прибрала `amount` і сіль, v4 — решту базового зі збережених даних.
- Група інгредієнтів (`group`): достатньо одного з групи («кріп або петрушка»).
- Приховування поки ручне повернення (`hiddenAt`).
- Фото зберігається як Blob в IndexedDB, стиснуте до 1280 px (JPEG).
- У формі група «або» — один пункт із кількома назвами; назва групи в базі генерується з назв (`кріп/петрушка`).
- Роутер — `createHashRouter` (потрібен для `useBlocker`: питання «Вийти без збереження?» на кнопку «назад»).
- Видалення страви — назавжди, з підтвердженням; також прибирає її з `pairs` інших страв.
- На сторінці страви біля кожного інгредієнта кнопка «Є / Немає»: натискання додає продукт у «Мої продукти» або прибирає звідти. Для групи «або» відкривається вибір, що саме є. Базове з `STAPLES` показується як «є завжди» і не перемикається.
- Пошук «Що приготувати» бере продукти з «Моїх продуктів». Заміна, що є вдома, закриває інгредієнт (у каталозі такий інгредієнт теж не потрапляє в «немає»). Для страви з варіантами береться варіант, де бракує найменше. «Хочу використати» — продукти мають бути інгредієнтами варіанта (заміни не рахуються). Посилання `/dish/:id?v=<id варіанта>` відкриває страву з цим варіантом.
- Пари — лише гарнір + білок, двобічні (id записується в `pairs` обох страв). Після редагування страви `prunePairs` прибирає пари, що перестали бути «гарнір + білок». Пари з прихованою стравою у вкладці «Пари» не показуються. «Навмання» обирає з готових пар (або з усіх, якщо готових немає).
- Резервна копія: один JSON (`app: "stravy"`, `version: 1`), фото всередині як data-URL. Імпорт **замінює все** (після підтвердження, з пропозицією спершу зберегти поточне); id страв зберігаються, бо на них посилаються `pairs`. Файл новішої версії не приймається.
- Базовий набір (`seed.ts`) — 41 страва зі списку користувачки (гарніри, м'ясо й риба, окремі страви, перші страви), з явними id 1…41, без фото й без пар. Стартові «Мої продукти» для нових користувачів порожні. У «Резервна копія» є «Базовий набір страв» — замінює лише страви, продукти лишаються.
- Оцінки страви (необов'язкові, 1–5): `effort` — складність (зірочки, кобальт), `love` — наскільки подобається (сердечка, персикові). Компоненти в `Rating.tsx`. Сортування «Найулюбленіші» і «Найпростіші» (без оцінки — у кінці); у пошуку й парах при рівності вище улюблені. Оцінки в базовому наборі взято з блокнота користувачки (`RATINGS` у `seed.ts`).
- Приклади додаються лише раз: позначка `seeded` у таблиці `meta` (з Dexie версії 2). Якщо видалити всі страви, приклади не повертаються.
- Файли не можна називати так, щоб вони відрізнялися лише регістром (`backup.ts` і `Backup.tsx`, `pairs.ts` і `Pairs.tsx`): на Windows це конфлікт. Файли з логікою називаємо `…Data.ts`.

## Команди
`npm install`, `npm run dev`, `npm run build` (тип-перевірка + збірка).
